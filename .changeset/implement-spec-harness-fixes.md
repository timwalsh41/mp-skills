`implement-spec` now coerces and validates its args before the first child launches, treats a launch the harness rejects as a configuration error instead of a ticket failure, and verifies each ticket's acceptance criteria independently before counting it as merged. A quoted numeric arg (`"900000"`) used to be rejected by the harness for every ticket in a run while looking like a broken implementation, and it was laundered through the remediation ladder into a bogus fixer, a bogus escalation and a dead run; the script now coerces the arg, fails once with a structured error if it cannot, and never blames a ticket for a configuration mistake. Each merged ticket additionally gets a `verifier` child that re-derives its acceptance criteria from the merged code — a missing verdict is not a pass, the ticket is escalated, and no request is opened over an escalated ticket. That verifier's task supplies the three inputs its role expects: the tracker doc to read the ticket through, the branch and spec reference to verify against, and the targeted-test command (`singleRetestCommand`, falling back to `docs/agents/verification.md`); it also names the answer heading the findings are appended under. The spec is now passed as a reference (`specRef`, either a path or the tracker ticket/epic that holds it), children get the tracker's read/update/resolve operations through a new `trackerHint` arg, the merger and fixer are handed the concrete location of a captured patch instead of being told to "inspect handoffs/", and every child carries a silence window longer than its gate so a test-suite-running child no longer wakes the lead to say it is quiet. The discovery child no longer declares an `outputSchema`: a step with one must finish by calling the harness's `structured_output` tool, so a model that answered with the JSON document as text — exactly what the task asks for — was rejected and the run died with "no tickets found" while the correct JSON sat in the child's output; the script parses that text itself. `setup-matt-pocock-skills` now makes sure the `docs/agents/` files it writes are not git-ignored: the tracked `AGENTS.md` points at them and the subagents read them from their worktrees, where a gitignored file does not exist.
